# glob選択仕様

`files: string[]`は常にリテラル。`globs: string[]`は管理形式version2の明示的なパターン配列であり、展開結果では置き換えない。

## 構文と基準

| 構文                | 意味・例                                                                          |
| ------------------- | --------------------------------------------------------------------------------- |
| `*`                 | 一つのパス区間の0文字以上。`adr/*.md`                                             |
| `?`                 | 一つのパス区間の1文字。`adr/?.md`                                                 |
| `[...]`             | 文字集合・範囲・先頭!/^の否定。POSIX名前付きクラスは非対応。`adr/[ab].md`、`[!a]` |
| 単独の`**`区間      | 0階層以上。`adr/**/*.md`は直下も含む                                              |
| `.`、`..`、絶対パス | 管理ファイルを基準に解決。プロジェクト内に限定しない                              |

各パス区間をNode標準のファイルシステムAPIで厳密に列挙し、小さな共通glob文法で照合する。ファイル名は全OSで大文字小文字を区別し、ロケール非依存の文字列順に並べる。Node標準glob自体のOS依存nocaseとエラー省略には依存しない。brace展開、extglob、先頭`!`の除外指定、regexは受け付けない。不正な未閉鎖の文字クラスや逆順の範囲も定義エラーとする。`..`は最初の可変ワイルドカードより前だけに使用でき（CWD文字を表す1文字のliteralクラスは可変としない）、ワイルドカード後の親移動は曖昧な正規化を避けるため明示的に拒否する。
文字としてのメタ文字は`[*]`、`[?]`、`[[]`、`[]]`などの文字クラスで指定できる。通常の個別パスならエスケープは不要。
区切りは`/`を推奨する。glob内の`\`はWindows入力との共通性のため区切りとして扱い、エスケープには使わない。
先頭`.`のファイルやディレクトリは`*`/`**`の暗黙対象に含めず、`.*`などで明示する。Gitのignore規則は使わない。

CLIの`--glob`は実行CWDを基準にし、管理ファイル基準のパターンへ変換する。CWDから付ける実パスのメタ文字はリテラル化する。
環境由来の相対prefixが先頭`!`になる場合は、`./!inputs/*.md`のように明示相対のliteralとして保存する。生の入力`!*.md`の除外構文拒否は維持し、create/add/removeを同じ変換へ通す。
シェルに展開させないよう`--glob 'docs/adr/**/*.md'`と引用する。繰返し指定でき、`--`より後の名前は個別ファイルのままである。

## 展開と検査

ディレクトリを直接読んでから各区間を共通文法で選択し、読取不能を標準globの空結果へ丸めない。
ディレクトリsymlinkには、明示した区間でも再帰でも降りない。通常ファイルsymlinkは参照先を読む。壊れた選択link・探索エラーは`GLOB_UNREADABLE`。
ディレクトリは実メンバーから除き、特殊ファイルが選択された場合は通常ファイルでないエラーにする。

個別パスを優先し、同じ解決済みパスに一致するglobを重ねても一件にする。glob由来のパスは管理ファイルからの相対パスを`/`で保存せず検査結果として提示する。
結果はパスの文字列順で安定化する。同じrealpathを指す別パスは`DUPLICATE_MEMBER`で拒否する。hardlinkは既存どおり別realpathとして扱い、このIssueでdev/ino同一を新しい禁止へ広げない。
Windowsの8.3名など、OSが受け付けるliteral別表記は、列挙名と同じentryであることを確認して選択する。返すパスは入力側の表記を保持する。大文字小文字だけの違いは別表記として受け入れず、wildcardの照合もcase-sensitiveのままとする。通常ファイルsymlink/ディレクトリsymlinkと探索エラーの扱いは変えない。物理ファイル識別と管理ファイル判定にはNode標準native realpathを使い、別表記による重複を見逃さない。HTMLの未作成出力先も同じliteral選択とnative解決したprefixで照合する。
各globの実ファイル一致0件は`GLOB_NO_MATCH`、合計2件未満は`TOO_FEW_FILES`。管理ファイル一致は`MANAGEMENT_FILE`。いずれもsnapshotを発行せず確認できない。

HTML出力の事前照合では、既存のliteral親だけをnative解決し、未作成の末尾literalや複数の親階層は選択式として残す。親aliasがあっても、literalだけのglobに一致する出力を作成しない。残した区間の`.`/`..`は字句照合と同じく正規化し、caseや文字クラスの意味は変えない。

動的検査では、全対象の読取り後に内容を再照合し、選択集合も再展開する。途中で集合が変われば`MEMBERS_CHANGED`で拒否する。
確認操作も同じ検査を行い、保存済みsnapshotと照合する。外部プロセスによる全FS操作の同時変更を原子的に封じるものではない。
Node24.16追加の`followSymlinks`オプションには依存しない。
