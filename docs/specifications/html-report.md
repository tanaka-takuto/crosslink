# HTMLレポート仕様

## 呼出しと終了コード

```sh
crosslink report --format html --output <path> [--file <group-file>] [--config <config.json>] [--json]
```

`--format html` と空でない `--output` をそれぞれ一回指定する。位置引数、別のformat、重複したformat/output、`--verbose` は拒否する。
`--file` は繰り返せる。重複を除いて管理ファイルの絶対パス順に検査する。指定しなければ `check` と同じ設定・探索規則を使う。
出力先と明示した管理ファイル・設定パスは実行ディレクトリを基準に解決する。出力先の親ディレクトリは事前に作成する。
`--json` はHTMLへ埋め込む形式を変えず、CLIの通知と検査結果を既存のJSON構造で出す。`operation` は `report`。

| 状況                                   | 終了コード | HTML                                                            |
| -------------------------------------- | ---------- | --------------------------------------------------------------- |
| 全対象が確認済み、または登録0件        | 0          | 生成する。0件は明記する                                         |
| 未確認あり、検査エラーなし             | 1          | 生成する                                                        |
| グループ構成不正・参照消失・破損JSON等 | 2          | 診断と描画できる検査結果を生成する                              |
| 設定・探索が失敗                       | 2          | 対象範囲の検査未完了として診断を生成する。0件の成功とは扱わない |
| 引数不正・書出し不能・出力衝突         | 2          | 新しいHTMLは保存しない。CLIへ診断を返す                         |

`HTML report saved: <absolute-path>` は書出し完了後だけ通知する。検査エラーと書出し失敗が併存するときも、取得済みのグループと診断はCLIの結果に残る。
HTML自体は `confirm --snapshot` へ渡すJSONではない。確認する場合は内容を読んだ後に `check --json` を改めて取得し、明示確認する。

## 表示と操作

- グループ総数・Confirmed・Unconfirmed・Groups with errorsを表示する。エラーのあるグループをUnconfirmedの件数へ重複計上しない。診断件数は別に表示する。
- 各グループの名前・理由・管理ファイル・全構成ファイル・診断を常時読める。確認記録のない読取可能なメンバーは `No baseline`、読取不能は比較値より優先して `Unreadable` とする。
- `Changed` / `Unchanged` は最後の確認との内容比較。構成の変更だけでもグループがUnconfirmedになりうる旨を表示する。
- グループの検索は名前・理由・登録パス・解決した絶対パス・管理ファイルパスに対する大文字小文字を区別しない部分一致。`Needs attention` は未確認と検査エラーを含む。`Clear filters` で検索と絞り込みを解除する。
- File indexはこの検査対象内の全構成ファイルを保持する。グループのフィルターでは隠さない。管理ファイルを基準に解決した同一絶対パスを同じファイルとしてまとめ、直接所属だけ列挙する。グループ名に依存しない内部IDでリンクし、同名グループも管理ファイルで区別する。
- 絞り込みで隠れたグループへ逆引きリンクをたどるとフィルターを解除し、その対象へフォーカスする。内部リンクとフォームはキーボード操作できる。
- `Open local file` は生成時の絶対パスからNode標準の `pathToFileURL` で構築する。HTMLの移動先や保存先からの相対解決は行わない。共有先で元ファイルが存在する保証はなく、ブラウザーによりローカルファイルの遷移が拒否される場合もある。各Groupsカードの操作付近にもこの制約と、隣のCopy pathまたは表示パスを利用できる旨を案内する。
- `Copy path` は絶対パスをコピーする。Clipboard APIが拒否・未提供なら、その場で選択可能な読取専用入力を表示する。パスは常に本文からも選択できる。
- 生成日時はUTCのISO文字列。versionはアプリ同梱版を取得する。範囲にはCWD・明示選択または探索・設定パス・検査完了の可否を表示する。
- JavaScriptが無効でも全グループとリンクを読める。検索・絞り込み・コピーボタンは内包スクリプトに依存し、無効時にはブラウザーの検索と表示パスの選択を案内する。

## 安全性と責務

HTML/CSS/JSを一つのHTMLへ内包し、外部リソースを取得しない。ファイル内容や差分は埋め込まないが、名前・理由・ローカルの絶対パスを含むので、共有前に内容を確認する。
ユーザーデータをテキスト/属性としてエスケープし、実行スクリプトのソースへ挿入しない。スクリプトはDOMのテキスト・属性・表示状態を扱い、HTML文字列として実行しない。
CSPは外部取得を禁止し、生成時にハッシュを計算した内包CSS/JSだけ許可する。ファイルリンクのスキームは `file:`、内部リンクは生成したIDの `#` に固定する。

アプリケーション操作が既存の `inspectGroup` と共通の結果集約を利用し、HTMLプレゼンターは検査結果を読み取って表示へ変換する。
出力アダプターは同じディレクトリに完成した一時ファイルを作ってから、既存先を置換しないリンク操作で公開する。既存ファイル・ディレクトリ・symlinkを上書きしない。
さらにアプリケーションは選択管理ファイル・取得済みメンバー・設定パスそのものを出力先に指定することを拒否する。消失メンバーや未作成の既定設定もレポートで作り直さない。
入力に対する確認・編集・削除は行わず、ブラウザーも自動起動しない。
