# 明示的な確認操作

## 要求

利用者がグループ全体を確認した事実と、その内容の組み合わせを明示的に記録できること。

## 要件

- 検査で得たグループ構成と全ファイルのハッシュを、確認操作の期待する状態として渡す楽観ロック方式とする。
- 確認操作で再取得した構成・ハッシュが検査時点と一致しなければ、確認を失敗させ、そのグループの確認記録を更新しない。
- 一致する場合に限り、検査で提示した組み合わせを確認済みとして記録する。
- 確認できた理由の入力や保存は要求しない。
- 「確認が必要な理由」はグループの関連性として別に保持する。
- 一つのグループを確認しても、他のグループの確認記録を自動更新しない。
- 複数グループの一括確認を提供する。ただし、明示的なオプションで有効にし、通常の確認操作に暗黙に含めない。
- 検査だけでは確認記録を更新しない。
- 古い・不正なsnapshotは拒否したまま、再検査して新しい内容を読み直し、新しい検査結果で明示確認するよう案内する。確認操作の繰り返しだけで解消するようには案内しない。
- 不正なグループには詳細検査で問題を特定・修復し、関連内容を読んでから確認するよう案内する。ロックは自動解除せず、更新が実行中でないことを確認する既存案内を維持する。

## 受入条件

- A・BとB・Cの両グループでBを変更し、前者だけを確認しても、後者は未確認のままである。
- 確認できた理由を入力せずに、グループの確認操作を実行できる。
- 一括確認を明示的に有効にした場合に限り、複数グループをまとめて確認できる。
- 検査でA・Bを提示した後、確認操作までにAの内容やグループ構成が変わると、確認操作が失敗し、そのグループの確認記録は変わらない。
- 古いsnapshot、壊れたsnapshot JSON、不正なversion・対象パス・重複対象・ハッシュを既存のコードで拒否し、対象と再検査・関連内容の読み直しを英語で案内する。失敗時に確認記録・対象内容・検査結果ファイルを変更しない。
- 不正グループの確認拒否には修復・読み直しを案内する。既存ロックを検出した場合は更新中でないことの確認を案内し、ロックと確認記録を保持する。
