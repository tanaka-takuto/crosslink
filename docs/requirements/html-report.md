# 単一HTMLレポート

## 要求

CLIの一覧だけで読み取りにくい、グループの理由・確認状態・共有ファイルの直接所属を、保存した一つのHTMLからたどりたい。
ローカルでもCIの成果物でも、外部サービスや常駐サーバーを用意せずに確認対象を把握できるようにする。
要求の起点は [Issue #19](https://github.com/tanaka-takuto/crosslink/issues/19)。

## 要件

- 明示された出力先へ閲覧用の単一HTMLを生成する。確認記録と構成ファイルは変更しない。
- `check` と同じ検査・判定を使う。グループ総数、確認済み、未確認、検査エラーのあるグループを分け、診断件数も表示する。
- 全グループの名前・理由・管理ファイル・全メンバーを表示する。メンバーは変更・未変更・比較元なし・読取不能を区別する。
- 名前・理由・管理ファイルと構成ファイルのパスで検索でき、未確認または検査エラーのあるグループへ絞り込める。フィルターは解除できる。
- グループからファイル、ファイルから対象範囲内の直接所属グループへ移動できる。同名グループは管理ファイルで識別できる。
- ローカルファイルのリンクと絶対パスのコピーを備える。保存先が実行ディレクトリと異なってもリンクは元ファイルを指す。開けない・コピーAPIを使えない場合も表示パスを取得できる。
- 生成時点、crosslinkのversion、実行ディレクトリ・選択対象・設定の範囲を示す。保存後に追従しないスナップショットであり、確認済みは意味的正しさの自動保証ではないと明記する。
- 固定UIは英語とし、入力した名前・理由・パスを保持する。ユーザーデータをHTMLやスクリプトとして実行せず、ユーザーデータから危険なURLスキームを生成しない。
- 登録0件は通知して成功する。未確認は1、不正・検査不能・書出し不能は2とする。描画可能な検査失敗はHTMLへ残す。探索・設定の失敗は対象0件の成功と区別する。
- 既存の出力・管理ファイル・構成ファイル・設定やソースを上書きしない。衝突時には別名を指定できるエラーを返す。
- 外部runtimeパッケージ、CDN、ネットワーク、Git、自動ブラウザー起動を必要としない。HTMLからの確認・編集、ライブ更新、グラフ、内容の差分は含めない。

## 受入条件

1. A・BとB・Cを確認後にBだけ変更すると、両グループが未確認になり、Bの2つの直接所属、理由、変更・未変更を表示する。片方のみ確認した再生成では確認状態を区別する。
2. 登録0件・確認済みのみ・未確認・比較元なし・消失ファイル・破損JSON・0/1ファイルを区別する。検査不能・書出し不能は2で終了し、可能な検査結果を保持する。
3. 出力先が別ディレクトリでも正しい絶対ファイルURLとコピー用パスを持つ。既存出力・symlink・入力先への衝突は元データを保持して拒否する。
4. 同名グループ、日本語、長いパス、多数グループ、HTML特殊文字を扱う。検索・要対応フィルター・逆引きがオフラインで動く。スクリプト不実行時も全件を読める。
5. 生成前後で入力内容と確認記録が変わらず、日時・version・範囲・スナップショットと確認の限界を表示する。
6. 最終HTMLを実装者とは別のUI/UXデザイナー役エージェントが実ブラウザーで確認する。表示・操作・キーボード・狭い画面・エラー表示の証拠を残し、重大・高の指摘があれば変更後の生成物を再レビューする。対象commit SHAとHTMLのSHA-256を結び付け、未実施を合格にしない。
