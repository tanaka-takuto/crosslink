# 整合性確認の自動検査

## 要求

CLIで確認状態を検査し、未確認や検査不能をCI等から検出できること。

## 要件

- 検査対象の全グループが確認済みの場合、成功とする。
- 一つでも未確認のグループがあれば、正常終了しない。
- 一つでも検査不能があれば、成功扱いしない。
- 構成ファイルが2件未満のグループがあれば、不正な構成として検査を失敗させる。確認記録の有無によって、この不正を解消したことにしない。
- 登録グループが0件の場合も成功とする。ただし、グループが登録されていないことを利用者が把握できるメッセージを出す。
- 登録グループが0件の場合と、登録済みグループの構成ファイルが0件の場合を区別する。
- 検査は確認記録を変更しない。
- 人間・機械処理・AIのいずれからも結果を利用できる。
- 通常checkは確認済み・未確認・不正の件数と、未確認・不正なグループを提示する。全ファイル・理由は `-v` / `--verbose` または `--json` で取得できる。

## 受入条件

- 未確認または検査不能のグループがあるとき、非ゼロ終了で検査を失敗させられる。
- 登録グループが0件なら成功し、英語で0件であることを通知する。
- 確認済みだけの通常checkは件数だけを表示する。未確認と不正が混在する場合も対象グループを省略せず、詳細表示へ案内する。
- 登録済みグループが一つでも0件・1件の構成であれば、対象グループとファイル数の不足を提示して非ゼロ終了する。CIでも同じ判定とする。
- ファイル読取不能や定義破損を、確認済みや単なる対象0件として扱わず、検査不能として失敗する。
