# 内容に基づく確認状態

## 要求

現在のファイル内容の組み合わせが確認されているかを判定し、古い確認で別の内容を確認済みにしないこと。

## 要件

- 確認状態は「確認済み」と「未確認」の2つとする。
- 新規登録と、確認後に内容が変わった場合を同じ未確認状態として扱う。
- 検査上有効な構成について、有効な確認記録と現在の構成・全ファイルのハッシュが一致する場合、確認済みとする。
- いずれかのハッシュが異なる場合、未確認とする。
- ファイルを最後に確認した内容へ完全に戻した場合は、確認済みに戻る。確認操作をやり直す必要はない。
- ファイルが変わったという履歴の検出は要求しない。現在の内容と保存された確認記録で判定する。
- グループの構成を変更した場合は既存の確認を引き継がず、未確認に戻す。
- 対象の消失や読取不能などは[対象の消失・定義の不整合・構成変更](invalid-references.md)の検査不能として扱う。
- 構成ファイルが2件未満の場合や、確認記録の保存先が関連対象に含まれる場合は、不正な構成として検査を失敗させる。確認状態の判定だけで成功させない。

## 受入条件

- 確認後、いずれかを異なる内容に変更すると未確認になる。再度確認した後に別のファイルが変わった場合も未確認になる。
- 確認後にAを編集し、再確認する前に全構成ファイルを最後に確認した内容へ戻すと、確認済みになる。
