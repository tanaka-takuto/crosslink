# 対象の消失・定義の不整合・構成変更

## 要求

対象ファイルの消失や定義の不整合を検知し、関連性の変更を正当に反映できること。

## 要件

- 削除・移動で登録パスにファイルがなくなった場合、無条件に確認済みとせず、検査不能として失敗する。
- ファイル読取不能、壊れた定義や確認記録、解釈できない形式では、検査不能として失敗する。
- 確認記録の保存先が関連対象に含まれている定義は不正として検出し、検査を失敗させる。
- 診断により、利用者が修復対象を特定できる。
- ファイル移動・グループ構成の変更を、明示的な操作で反映できる。
- メンバーの追加・削除・登録パスの変更で構成を変えた場合、未確認に戻し、確認し直す。
- 編集途中の0件・1件の構成は保存できるが、検査では不正として失敗する。メンバーの入れ替えを完了して2件以上に戻した後も、構成変更後の確認を必要とする。
- 相対パスは管理ファイルの位置を基準に解決し、絶対パスも使用できる。プロジェクトルートへの所属は要求しない。

## 受入条件

- 登録したファイルを削除・移動すると、修復対象を特定でき、検査は失敗する。
- 確認済みグループのメンバーや登録パスを変更した場合、ファイル内容が同じでも未確認になる。
- 手動編集などで確認記録の保存先が関連対象に含まれた場合も、不正な関連付けを診断して検査を失敗させる。
- A・BからBを外して一時的にAだけにし、その後Cを追加する操作を保存できる。Aだけの時点では検査が不正として失敗し、A・Cになった後は構成変更後の確認を必要とする。
