# 変更影響の可視化

## 要求

何が変わり、どのファイルを、なぜ確認する必要があるかを把握できること。

## 要件

- 詳細表示とJSONでは、確認対象のグループ、全構成ファイル、最後の確認時点から変更されたファイル、未変更の確認対象、現在の確認状態を提示する。
- 詳細表示とJSONでは、グループに記録した「確認が必要な理由」を提示する。
- ファイルを指定し、直接所属するグループと、そのグループの他の構成ファイルを逆引きできる。
- 人間向け・機械処理向け・AI向けの利用を考慮した結果を提供する。
- CLIの人間向け標準出力にはテキストを、機械処理とAIには共通のJSONを提供する。明示した出力先へ保存する[HTMLレポート](html-report.md)も提供する。
- CLIの固定文言は英語に統一し、利用者が入力した名前・理由・パスは保持する。
- 通常checkは状態別件数と未確認・不正なグループに絞る。`-v` / `--verbose` で全グループ・理由・全ファイルを表示する。
- `--json` は人間向け表示の省略にかかわらず完全な情報を維持する。
- ファイル内容の差分表示は不要とする。確認対象を特定できる情報を提供する。

## 受入条件

- A・BのAだけを変更すると、詳細表示とJSONでAを変更ファイル、Bを未変更の確認対象として提示する。
- 変更グループと構成ファイルを特定でき、ファイルからグループ・関連ファイルを逆引きできる。
- 通常checkは確認済みグループの全ファイルを表示せず、状態別件数と未確認・不正なグループを表示する。
- `-v` と `--verbose` はともに全グループ・全構成ファイル・理由を表示し、`--json` の情報量を変えない。
- help・成功・失敗・診断・状態は英語になり、日本語の利用者データもそのまま表示される。
